Assignment 7: DoS/DDoS Detection & Website Availability

Network traffic analysis • Machine learning • AI educational movie

Research problem and objectives

Denial-of-Service (DoS) attacks attempt to make online services unavailable by overwhelming resources or exploiting service weaknesses. Distributed Denial-of-Service (DDoS) attacks involve traffic from multiple sources. Our research question is: Can data-driven methods help detect abnormal network traffic associated with DoS/DDoS attacks?

We aim to compare benign and malicious network flows, identify abnormal traffic patterns, and evaluate a supervised classifier. Detection can support mitigation decisions but does not itself guarantee website availability.

Dataset

We use CIC-IDS2017 from the Canadian Institute for Cybersecurity, University of New Brunswick. The public dataset contains labeled network flows including benign, DoS and DDoS activity. Our analysis uses the Wednesday DoS and Friday afternoon DDoS CSV files, which also include benign traffic.

Official dataset · Hugging Face dataset

Selected features include flow duration, packet counts, bytes and packets per second, packet lengths, and TCP flag counts. The Label column distinguishes BENIGN, DoS variants and DDoS.

Data preparation and methodology

Load the selected CSVs, standardize column names and labels, keep relevant classes, remove duplicate rows, convert numeric features, and replace infinite values with missing values. Split the data 80/20 with stratification and random state 42. Fill missing values using training-set medians. Train a Random Forest classifier and evaluate on the held-out test set.

Our analysis compares class counts and distributions of flow packets/second and bytes/second. It also summarizes feature medians and feature importance. A flow is not the same as a request, so flow counts are not direct measurements of website request rate.

Traffic analysis

Normal traffic: Benign flows can show a range of durations, rates and packet sizes associated with ordinary network activity.

Attack traffic: Some attacks produce unusually high flow rates, packet bursts or repeated requests; low-rate DoS attacks may instead have prolonged connections. No single metric reliably identifies every attack.

Abnormal behavior: Compare traffic against a baseline using flow rate, packet/byte rates, duration, flags and model predictions. False alarms are possible during legitimate traffic spikes.

Conclusion and limitations

Network-flow features provide a practical way to investigate possible denial-of-service activity, and supervised learning can be evaluated for identifying known attack patterns. Final conclusions about model effectiveness depend on the actual test results.

The dataset dates from 2017, is captured in a controlled environment, and may not represent current traffic. A random flow split can overestimate real-world performance because similar traffic patterns can appear in both training and test data. Future work could evaluate newer datasets, time-based splits, false positive rates, detection latency and deployment alongside rate limiting or traffic filtering.
